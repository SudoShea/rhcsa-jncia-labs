## 🎯 Objectives

By the end of this lab, you will be able to:
1. Configure `systemd-journald` to store system log journal files persistently across system reboots.
2. Manage log storage limits, rotation rules, and disk space retention caps in `journald.conf`.
3. Query and filter system log data using `journalctl` by service unit, severity priority, time range, and executable path.
4. Export and inspect boot-specific journal entries and manually vacuum archived journal logs.

---

## 📋 Prerequisites

* A running RHEL 10 lab virtual machine.
* Administrative access via `sudo` or the `root` account.

---

## 🛠️ Scenario

Your team is investigating intermittent service failures on a production RHEL 10 host. Upon rebooting the server to troubleshoot, you discover that previous log messages were lost because `systemd-journald` was storing logs in volatile memory (`/run/log/journal`). You must enable persistent log storage, restrict total journal disk usage to prevent filesystem exhaustion, and perform structured log analysis to isolate historical system events.

---

## 📝 Lab Tasks

### Task 1: Persistent Journal Storage Configuration
1. Inspect the current journal storage configuration and verify if `/var/log/journal` exists.
2. Configure `systemd-journald` to enforce persistent log storage by creating a drop-in configuration file at `/etc/systemd/journald.conf.d/00-persistent.conf` containing `Storage=persistent`.
3. Create the persistent log directory `/var/log/journal` with appropriate directory permissions (`2755` owned by `root:systemd-journal`) if required.
4. Restart the `systemd-journald` service or send a flush signal (`systemctl reload systemd-journald`) to flush volatile logs from RAM to `/var/log/journal`.

### Task 2: Journal Space Management & Retention Limits
1. Query current disk usage of the persistent system journal using `journalctl`.
2. Configure a drop-in file at `/etc/systemd/journald.conf.d/01-limits.conf` setting `SystemMaxUse=500M` and `SystemKeepFree=1G`.
3. Reload `systemd-journald` to apply storage limits.
4. Perform a manual log vacuum operation to trim archived logs down to a maximum of `200M` or retain only logs from the last `2d` (2 days).

### Task 3: Structured Log Queries with `journalctl`
1. List all recorded system boots stored in the persistent journal database.
2. Query logs generated specifically during the current boot cycle (`-b 0`).
3. Filter logs to show only entries with severity level `err` (errors) or higher generated by the `sshd` unit.
4. Search for entries across all units generated within the last 30 minutes, formatting the output in human-readable UTC timestamp lines.
5. Continuously tail active incoming log streams for the `firewalld` service in real time.

## 💡 Step-by-Step Solution & Reference
Task 1 Solutions: Persistent Storage Configuration
```bash
# 1. Inspect current journal directory state
ls -ld /var/log/journal 2>/dev/null || echo "Directory does not exist"

# 2. Create drop-in directory for configuration overrides
sudo mkdir -p /etc/systemd/journald.conf.d/

# 3. Configure persistent storage setting
sudo cat << 'EOF' | sudo tee /etc/systemd/journald.conf.d/00-persistent.conf
[Journal]
Storage=persistent
EOF

# 4. Create directory and set POSIX group ownership and permissions
sudo mkdir -p /var/log/journal
sudo systemd-tmpfiles --create --prefix /var/log/journal

# 5. Reload systemd-journald and flush logs
sudo systemctl restart systemd-journald
sudo journalctl --flush
```
Task 2 Solutions: Retention Caps & Vacuuming
```bash
# 1. Query disk usage
journalctl --disk-usage

# 2. Configure max usage limits
sudo cat << 'EOF' | sudo tee /etc/systemd/journald.conf.d/01-limits.conf
[Journal]
SystemMaxUse=500M
SystemKeepFree=1G
EOF

# 3. Reload journal service
sudo systemctl restart systemd-journald

# 4. Manually vacuum archives by size and time
sudo journalctl --vacuum-size=200M
sudo journalctl --vacuum-time=2d
```
Task 3 Solutions: Log Queries & Filtering
```bash
# 1. List recorded system boots
journalctl --list-boots

# 2. Show logs from current boot
journalctl -b 0

# 3. Filter by unit and priority level (0=emerg, 1=alert, 2=crit, 3=err)
journalctl -u sshd -p err

# 4. Filter by time window (since 30 minutes ago)
journalctl --since "30 min ago"

# 5. Tail live output stream for a specific service
journalctl -u firewalld -f
```
